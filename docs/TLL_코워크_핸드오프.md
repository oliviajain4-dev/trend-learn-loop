**소스 결정 (기획 단계에서 합의)**

## 3. 반드시 지킬 원칙 (프로젝트 DNA)

1. **측정 없는 주장 금지 / 반환각.** '신뢰도'는 감이 아니라 숫자. 근거 약하면 채우지 말고 "미확인"으로 남기고 신뢰도 하향.
2. **링크·수치는 API 원본에서만.** LLM이 URL·조회수·스타수를 지어내게 두지 말 것. 코드로 삽입.
3. **검증 코어는 결정론(비에이전트).** L1 인용 앵커링(인용문이 원문에 문자열로 실제 존재하는지 코드 대조)은 LLM 판단 0. 여기에 자율성 넣지 말 것. (이유는 `TLL_평가_에이전트기반_v1.md` §5)
4. **에이전트 경계를 정직하게 라벨링.** 기본은 워크플로우. 에이전트는 "재수집/재집필 결정" 같은 지점에만 얇게. "에이전트 만들었다"를 과장하지 말 것. (v2.1 §2.5)

## 4. ★ 과제 맥락 — 이게 작업 방식을 바꾼다 (중요)

이 프로젝트는 **채용 사전 과제**다. 평가자는 결과물의 완성도보다 **"AI를 어떻게 부렸는가"**를 본다. 특히 **가장 중요한 제출물은 "AI 활용 기록"** — 프롬프트 → AI 답변 → 사용자의 의심·수정·재요청, 그리고 **AI가 틀린 순간과 그걸 바로잡은 과정**이다.

**따라서 코워크는 구현과 병행해 다음을 반드시 남긴다:**
- `WORKLOG.md` — 무엇을 시도했고, 어떤 도구를 썼고, 무엇이 실패했고, 어떻게 복구했는지 시간순 기록. **특히 "여기서 막혔다 → 이렇게 뚫었다"를 솔직하게.**
- `ERRORS.md` — AI(코워크 자신 포함)가 틀렸거나 엉뚱하게 답한 순간과 수정 내역. 이게 과제의 핵심 증거물이다.
- 완벽하게 다듬지 말 것. **날것의 과정이 오히려 높은 평가를 받는다.**

즉 코워크는 "조용히 잘 만드는" 게 아니라 **"과정을 드러내며 만드는"** 모드로 일해야 한다.

## 5. 코워크가 먼저 할 일 (계획 → 확인 → 착수)

**곧바로 코딩하지 말 것.** 순서:

### 5-1. 계획 제안 (첫 산출물)
아래를 담은 **간결한 착수 계획**을 사용자에게 먼저 제시하고 승인을 받는다:
- Phase 1을 어떤 하위 단계로 쪼갤지 (v2.1 §11 참고하되, 코워크가 판단해 조정 가능)
- 각 단계의 "동작하는 최소 결과물"과 검증 방법(어떻게 '됐다'를 확인할지)
- 어디를 워크플로우로, 어디에 첫 에이전트 훅(권장: 전환점 1 재수집 결정)을 얹을지
- 리스크와 그 완화책

### 5-2. 코딩 규약 스스로 제안 (사용자에게 확인만)
사용자는 규약을 직접 지정하지 않기로 했다. **코워크가 아래를 스스로 정해 제안하고, 한 줄 확인만 받아 확정**한다:
- 언어·런타임(현재 .venv Python 3.10 기준 — 유지할지, 이유와 함께)
- 폴더/모듈 구조 (v2.1 §9 모듈 지도를 실제 디렉터리로 번역)
- 의존성 관리 방식(requirements.txt vs 기타)·LLM 프로바이더 추상화 구조
- 커밋 단위·메시지 스타일, 브랜치 전략
- 설정·비밀키 로딩 방식(.env 로더), 로깅 방식
- 코드 스타일/포매터(예: black, ruff 등 — 쓸지 말지)
제안엔 **왜 그렇게 정했는지 1줄 근거**를 붙인다(프로젝트 정신: 근거 있는 선택).

### 5-3. 착수
승인 후 첫 단계 구현. 각 단계 끝에서 **동작 확인 + WORKLOG 갱신** 후 다음으로.

## 6. 체크포인트 규칙 (human-in-the-loop)
- 되돌리기 어려운 결정(폴더 구조 확정, 큰 의존성 추가, 원격 푸시) 전에는 **짧게 확인**을 받는다.
- 각 하위 단계 완료 시 "무엇이 됐고 / 어떻게 확인했고 / 다음은 무엇" 3줄 요약.
- 막히면 혼자 오래 헤매지 말고, 시도한 것과 막힌 지점을 요약해 사용자에게 공유(그 자체가 과제 증거물).

```
- TLL_평가_논문기반_v1.md  ← 품질·검증 설계 근거

핸드오프 문서 §5대로, 코드는 아직 짜지 말고:
1) Phase 1 착수 계획을 제안하고
2) 코딩 규약(언어·폴더구조·커밋 스타일 등)을 네가 스스로 정해 근거와 함께 제안해줘.
내가 승인하면 그때 착수하자.

그리고 §4대로, 작업하면서 WORKLOG.md와 ERRORS.md에
'무엇을 시도했고 뭐가 틀렸고 어떻게 고쳤는지'를 솔직하게 계속 남겨줘.
이건 채용 과제라 그 과정 기록이 결과물보다 중요해.
```
