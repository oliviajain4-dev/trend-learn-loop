# TLL 설계 평가 — 논문 기준 채점 & 개정안 (v1 → v2)

> 작성: 2026-07-10 · 목적: 사용자의 프롬프트나 나(에이전트)의 즉흥이 아니라 **동료심사된 학술 문헌**을 외부 기준으로 삼아 TLL 기획서 v1을 평가·수치화하고, 그 근거로 v2로 개정한다.
> **정직 고지**: 아래 점수는 "논문에서 도출한 기준에 대한 전문가 판단"이다. **실제 벤치마크를 돌린 실측치가 아니다.** 실측치처럼 포장하는 것은 이 프로젝트(반환각)의 정신에 어긋나므로 명시한다. 실측은 v2의 평가 하네스로 구현 후 가능.

---

## 0. 근본 프레이밍 재정의 (사용자 문제 제기 반영)

사용자 지적: "'배울지 말지'가 근본이 맞나? 먼저 정체를 제대로 밝혀야 하고, 기존 개념과 엮어 뭐가 비슷/다른지 한눈에. 더 근본적인 게 있나?"

**결론: '배울지 말지'는 근본이 아니다. 부산물이다.**

| 층위 | 프레이밍 | 문제 |
|---|---|---|
| 표층 | "이걸 배울지 말지 결정해준다" | 이진 추천기로 전락. 얕은 심판. |
| 중간 | "이게 뭔지 정확히 이해시킨다" | 방향은 맞으나 '왜'가 빠짐. |
| **근본** | **"불확실성을 줄이고 방향을 잡게 한다 (orientation)"** — 이게 뭐고·믿을 만한가·내가 아는 것과 어디서 만나고·나에게 무슨 의미인가 | 좋은 이해가 서면 '배울지/쓸지/추적할지'는 저절로 따라 나옴 |

**북극성 재정의**: TLL은 "판단해주는 에이전트"가 아니라 **"신뢰할 수 있는 이해를 빠르게 형성하는 엔진"**이다. 성공의 1차 지표는 추천 정확도가 아니라 **산출된 이해의 충실도(faithfulness)** 이다.

문헌 근거:
- Deep Research 에이전트는 이 일을 "판단"이 아니라 **knowledge synthesis(지식 종합)** — 자율적으로 찾고·분석하고·종합해 근거 있는 이해를 만드는 것으로 정의한다. (Deep Research survey, arXiv:2508.12752)
- "뭐가 비슷/다른가"는 인지과학의 **대조·유추 설명**이며, 인간이 새 개념을 이해하는 근본 메커니즘이다. → TLL의 핵심 산출 방법으로 승격.

## 1. 문헌 근거 (실제 논문, 검증됨)

| # | 논문 | 출처 | TLL에 주는 것 |
|---|------|------|---------------|
| P1 | **STORM** — Assisting in Writing Wikipedia-like Articles From Scratch with LLMs | NAACL 2024, Stanford OVAL (Shao et al.) | 근거·인용 있는 장문 생성의 2단계(연구→집필), **다관점 질문 생성(multi-perspective question asking)** |
| P2 | **ALCE** — Enabling LLMs to Generate Text with Citations | EMNLP 2023, Princeton (Gao et al.) | 3축 평가: **fluency / correctness / citation quality**, 인용 품질을 **NLI**로 측정 |
| P3 | **Chain-of-Verification (CoVe)** | Meta, ACL Findings 2024 (Dhuliawala et al.) | 검증을 **독립 검증질문으로 분리**해 초안 편향 차단(초안→검증질문→독립답변→수정). F1 +23% |
| P4 | **FActScore** — Fine-grained Atomic Evaluation of Factual Precision | EMNLP 2023, UW (Min et al.) | 생성물을 **atomic fact 단위로 분해**해 신뢰 출처가 지지하는 비율을 측정(자동화 오차 <2%) |
| P5 | **Reflexion** — Language Agents with Verbal Reinforcement Learning | 2023 (Shinn et al.) | 자기개선을 **Actor / Evaluator / Self-Reflection + 에피소드 메모리**로 구조화. 반복 학습으로 성능 향상 |
| P6 | **RAGAS** — RAG 평가 프레임워크 | 오픈소스/논문 | 참조 없이 **faithfulness / answer relevancy / context precision·recall** 자동 측정 |
| P7 | **Deep Research: A Survey of Autonomous Research Agents** + 벤치(ReportBench, DEER) | arXiv:2508.12752 (2025) 등 | TLL이 속한 분야(deep research agent)를 명명·구조화: planning→question developing→web exploration→report generation |

핵심 교훈 한 줄: **"검증하겠다"는 설계로는 부족하다. 문헌은 하나같이 '충실도를 숫자로 측정하고, 검증 절차를 분리하며, 그 결과를 벤치마크로 확인'할 것을 요구한다.**

## 3. 채점: v1(현재) vs v2(개정)

| 기준 | v1 | 근거(v1) | v2 | 개정 내용 |
|------|:--:|---------|:--:|-----------|
| C1 충실도 측정 | 3.0 | 근거 원칙은 있으나 충실도를 **숫자로 산출하지 않음** | 4.5 | brief마다 **atomic-fact 지지율(FActScore식) + RAGAS faithfulness** 계산, '신뢰도'를 실수치로 |
| C2 검증 엄밀성 | 2.5 | 교차모델 심판은 있으나 **CoVe식 독립 검증질문** 없음 | 4.5 | Verifier를 **CoVe 구조**(초안→검증질문 생성→독립 답변→수정)+결정론 앵커링으로 재설계 |
| C3 인용 품질 | 2.5 | provenance·[S#]는 있으나 **인용 정밀도/재현율 미측정** | 4.0 | **NLI 기반 인용 품질**(지지되는가·불필요 인용 없는가) 지표화 |
| C4 다관점 연구 | 2.0 | Detector→Analyst 단발, 관점 없음 | 4.0 | 집필 전 **STORM식 다관점 질문 생성**(개발자/회사/회의론자/사용자 관점) |
| C5 평가 하네스 | 1.5 | 임시 단위테스트뿐, 지표 하네스 없음 | 4.0 | **미니 벤치마크**(잘 아는 기술 셋)로 atomic-fact 정밀도·인용 P/R·**환각 검출률** 측정 |
| C6 자기개선 | 2.5 | lessons 테이블(비정형) | 4.0 | **Reflexion 구조**(Actor=Analyst, Evaluator=Verifier+지표, Self-Reflection=lessons 메모리)+반복 측정 |
| C7 개념 연결 | 2.5 | '비교' 섹션은 있으나 방법 없음 | 4.0 | **대조·유추 설명**을 명시 방법으로: 사용자 KB의 기존 개념에 앵커링 |
| C8 트렌드 탐지 | 3.0 | 휴리스틱 모멘텀/신규성 | 3.5 | 약신호(weak-signal) 보강(부차) |
| C9 단순성 | 4.5 | 깔끔한 핵심 우선안 | 3.5 | 엄밀성↑ → 복잡도↑(정직한 트레이드오프). 옵션 스위치로 완화 |

### 가중 총점
```
v1 = 20·0.60 + 15·0.50 + 12·0.50 + 12·0.40 + 12·0.30 + 10·0.50 + 10·0.50 + 5·0.60 + 4·0.90
   = 12 + 7.5 + 6 + 4.8 + 3.6 + 5 + 5 + 3 + 3.6  ≈ 50.5 / 100
v2 = 20·0.90 + 15·0.90 + 12·0.80 + 12·0.80 + 12·0.80 + 10·0.80 + 10·0.80 + 5·0.70 + 4·0.70
   = 18 + 13.5 + 9.6 + 9.6 + 9.6 + 8 + 8 + 3.5 + 2.8  ≈ 82.6 / 100
```

## 4. v1의 결정적 약점 4가지 (문헌 대비)

1. **충실도를 측정하지 않음** — "환각 없게 하겠다"면서 환각률을 재는 수단이 없었다. 문헌(P4,P6)은 측정 없이는 개선도 신뢰도 주장도 불가라고 본다.
2. **검증이 초안에 편향됨** — 같은 문맥에서 검증하면 초안의 오류를 답습. CoVe(P3)는 검증을 **독립 질문**으로 떼어내야 효과가 있음을 보였다(F1 +23%).
3. **연구가 단관점** — 한 번의 집필로는 회의론·반대 근거를 놓친다. STORM(P1)의 다관점 질문이 커버리지·균형을 만든다.
4. **자기 검증의 검증 부재** — 내가 설계한 검증기가 실제로 거짓을 잡는지 확인하는 벤치마크가 없었다. 이게 사용자가 가장 강조한 지점인데 v1이 가장 약했던 곳.

## 5. v2 개정 설계 요약 (반영 후)

**파이프라인 (Deep Research 4단계 + 검증 강화)**
```
Planning → Multi-perspective Q 생성(STORM) → Web/API 수집(provenance)
   → 집필(문장별 [S#]) → 검증(CoVe: 검증질문→독립답변→수정 + L1 앵커링 + NLI 인용)
   → 지표 산출(atomic-fact 지지율·RAGAS faithfulness·인용 P/R)
   → 산출(신뢰도 실수치 표기) → Loop(Reflexion: 반복마다 지표로 개선)
```

**핵심 산출물 변화**
- '신뢰도'가 별점 감(感)이 아니라 **측정된 숫자**(예: atomic-fact 지지율 92%, 인용 정밀도 0.88).
- '비교' 섹션이 **대조·유추 설명**으로: "X는 Y와 구조는 같으나 Z에서 다르다" 를 KB의 기존 개념에 연결.
- **평가 하네스**가 별도 산출: 검증기가 심은 가짜 문장을 몇 % 잡아냈는지 → 과제의 "AI 오류 검출" 증거로 직결.

**구현 순서 변화 (Phase 1 재정의)**
1. shared/llm(provider 추상화)
2. 수집(무키 소스) + provenance
3. 집필(문장별 인용)
4. **검증 = CoVe + 결정론 앵커링**
5. **평가 하네스 = atomic-fact 정밀도 + 환각 검출률** ← 신규, Phase 1에 포함(측정 없이는 v2의 의미 없음)
6. 한 페이지 산출 + 신뢰도 실수치

## 6. 방법론 정직 고지 (재강조)

- 3장의 점수는 **논문 기준에 대한 구조화된 전문가 판단**이며 실측 벤치마크가 아니다.
- v2의 C5(평가 하네스)를 구현하면, 그때부터 **실측 충실도·환각 검출률**로 이 표를 대체할 수 있다. 그 전까지 이 수치는 "설계 성숙도의 상대 비교"로만 읽어야 한다.
- 이 고지 자체가 TLL이 지향하는 태도(측정 없는 주장 금지)의 예시다.
