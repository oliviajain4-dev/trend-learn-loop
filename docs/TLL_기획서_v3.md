# TLL (Trend · Learn · Loop) — 기획서 v3 (자율 에이전트 재설계)

> 작성: 2026-07-10 · 상태: **방향 확정, 구현 착수 직전** · v2.1의 강조점을 전환
> 상위 문서: `TLL_기획서_v2.1.md`(검증·충실도 설계는 이 문서로 계승하되 **배경으로 재배치**),
> `TLL_현황_핸드오프_Phase1.md`(Phase 1 실구현 현황).
> 근거: 사용자 방향 재확정 + 에이전트 문헌(CoALA · ReAct · Reflexion · Anthropic · STORM/Co-STORM · Deep Research survey).

**v2.1 → v3 한 줄:** "측정된 충실도"를 북극성으로 두던 것을, **"스스로 최신 기술을 찾아 실시간으로 한국어 교과서를 만드는 자율 에이전트"**로 전환한다. 충실도는 북극성에서 내려와 **최신성을 가능케 하는 배경 장치**로 재해석한다(없애지 않는다).

---

## 0. 한 줄 정체

> **사람이 주제를 주지 않아도**, 에이전트가 스스로 최신 IT/AI 기술을 찾아내 공식 문서를 읽고,
> "이게 뭔지 · 기존과 뭐가 어떻게 다른지"를 **실시간으로 한국어 교과서**로 만들어 쌓는다.

---

## 1. 왜 바꾸나 (v2.1의 문제)

- v2.1은 "측정된 충실도"를 전면에 뒀다. 그 결과 눈에 보이는 게 검증·지표라 프로젝트가 얌전하고 임팩트가 약했다.
- 진짜 원하는 것 세 가지: **① 자율성**(주제를 스스로 발견) · **② 신선도**(어제·1시간 전 것도) · **③ 한국어로 한눈에**.
- 충실도는 버리지 않고 **자리를 옮긴다.** 최신 기술은 모델이 모르므로 원문을 그 자리에서 읽어야 하고, 그 **원문 대조가 곧 충실도**다. 즉 충실도는 최신성의 부산물이자 안전벨트 — 자율 루프가 지어낸 교과서를 걸러내 신선함을 안전하게 만든다.

---

## 2. 3대 원칙 (바뀐 우선순위)

1. **자율 발견 우선** — 다음 행동(무엇을 볼지 · 더 팔지 · 쓸지)을 코드가 아니라 **모델이 고른다**.
2. **실시간 신선도가 심장** — 1시간 전 것도 잡는다. **모델 기억을 믿지 말고 원문을 그 자리에서 읽는다**(모델은 방금 나온 걸 모른다 — 이 에이전트를 만드는 클로드조차 지식이 과거에 멈춰 있다).
3. **한국어 우선, 원문은 한 클릭** — 번역해서 편하게 한눈에, 밑에 원문 링크로 대조 가능하게.

---

## 3. 에이전트 작동 순서 (이 문서의 척추 — 빌드도 이 순서로)

에이전트가 한 사이클에 실제로 도는 순서. 각 단계에 **[에이전트]=모델이 결정** / **[결정론]=코드가 실행** / **[인프라]** 를 표시한다.

```
⏱ Scheduler → 🔭 Scout → 🧭 Triage → 🔗 Tracker → 📖 Reader → ✍️ Author → 🛡️ Fact-Check → 🧠 Memory → 📊 Dashboard ↺
                                          ↑______________ "더 찾자"(ReAct) ______________|
```

| # | 단계 | 하는 일 | 입력 → 출력 | 종류 |
|---|------|---------|-------------|------|
| 0 | **Scheduler / Watcher** | 주기적으로 사이클을 깨움(빠른 감시) | 시각 → 트리거 | 인프라 |
| 1 | **Scout 정찰** | 실시간 소스(3급 신호)를 훑어 트렌드 후보를 뽑고, 기억과 대조해 **새 것만** 남김 | 소스 → 신규 후보 목록 | 결정론 (발견·신규성) |
| 2 | **Triage 선별** | 후보 중 "교과서 감 vs 소음", "새 주제 vs 기존 업데이트"를 판단. 사이클당 상위 N개만 | 후보 → 채택 주제 | 에이전트 |
| 3 | **Tracker 추적** | 채택 주제의 **공식 문서·논문(1급)으로 링크를 타고** 들어가 **본문**을 가져옴 | 주제 → 원문 본문 | 에이전트가 소스 선택 → **본문 fetch는 결정론** |
| 4 | **Reader 독해** | 본문을 읽고 "이게 뭔지" 파악. 근거 부족하면 **"더 찾자"**를 스스로 선택해 3으로 되돌림 | 본문 → 이해/부족판정 | 에이전트 = **ReAct 결정점** |
| 5 | **Author 집필** | 한국어 교과서 집필: **대조·유추 중심**, 문장별 `[S#]`, **한국어 번역 + 원문 텍스트 보존**. 대조 근거는 기억에서 당김 | 이해 → 교과서 초안 | 에이전트 |
| 6 | **Fact-Check 검증** | ① 인용이 원문에 문자열로 있나(L1) ② **한국어 번역이 원문을 왜곡 안 했나**. 위반은 삭제/미확인 | 초안 → 검증된 교과서 | **결정론** |
| 7 | **Memory 갱신** | 배운 개념을 KB에 축적(다음 대조 근거) + 실패를 lessons에 기록(Reflexion) + "본 것" 표시 | 결과 → 기억 갱신 | 에이전트가 씀 / 저장은 결정론 |
| 8 | **Dashboard 산출** | 한국어 통합 뷰: 신선도("1시간 전")·충실도 배지·원문 링크, 최신순 | 교과서 → 화면 | 인프라 |

> 되돌림은 4→3(더 찾자)만이 아니라, Reader가 판단하면 1(Scout)까지 되돌아 다른 소스를 더 칠 수 있다. 이 되돌림 선택권이 "진짜 에이전트"의 핵심이다.

---

## 4. 신선도 메커니즘 (1시간 전 것을 잡는 법)

- **실시간 소스를 자주 훑기** — 해커뉴스 프론트페이지·RSS는 새 글이 분 단위로 뜬다. (현재 코드 `collector/trends.py`에 HN 실시간 피드가 이미 있음.)
- **"지난 확인 이후 새 것만"** — 기억에 마지막 확인 시각·`seen` 목록을 두고 비교. 같은 것 재작업 안 하고 새 것만 낚아챔.
- **두 박자 분리** — 빠른 **감시(watcher, 10~15분)** 로 "새 거 떴나?"만 가볍게 확인 + 무거운 **집필(builder)** 은 진짜 새롭고 가치 있는 게 뜰 때만. 30분 고정보다 반응이 빠름.
- **화면에 신선도 박제** — "1시간 전 · 어제"를 표시하고 최신순 정렬.
- **정직 고지** — arXiv 등 일부 1급 소스는 하루 단위 갱신이라 "1시간"이 아니라 "어제" 수준이 한계. 커뮤니티·RSS·릴리스 피드는 분 단위. 소스별 신선도 한계를 그대로 표기한다.

---

## 5. 소스 등급 (신호와 근거를 섞지 않는다)

| 등급 | 무엇 | 역할 |
|:--:|------|------|
| **1급** | 공식문서 · 논문 (arXiv · 공식 도메인) | **"이게 뭔지"의 근거** |
| **2급** | 뉴스 · 기관 | 보조 |
| **3급** | 커뮤니티 (HN · GeekNews · GitHub) | **"떴다" 신호만** |

- 규칙: **신호는 3급에서, 근거는 1급에서.** 커뮤니티 잡담으로 설명을 채우지 않는다.
- 1급 근거가 없으면 채우지 말고 **"아직 확실한 자료 없음"** 으로 정직 표기(등급은 도메인으로 자동 판정 — 기존 `grade_from_domain` 재사용).

---

## 6. 검증의 새 자리 (배경 — 그러나 없애지 않음)

- **L1 결정론 인용 앵커링** — 교과서 문장의 인용이 원문에 문자열로 실제 존재하는지 코드로 대조(기존 `verifier/anchoring.py`).
- **번역 대조 (신규 검증면)** — 한국어가 원문 의미를 왜곡하지 않았는지. **번역도 환각할 수 있으므로 원문 텍스트를 반드시 저장**하고 대조·원문 링크 제공.
- 나머지(FActScore · RAGAS · CoVe · L2~L6 · 하네스)는 **배경/후순위**로 유지. 주인공 아님.
- **왜 남기나:** 자율 루프가 지어낸 교과서면 무용지물. 검증 게이트가 통과분만 게시해 **신선도를 안전하게** 만든다. 이게 흔한 자동요약봇과의 차별점.

---

## 7. 기억(Memory / KB) — "나중"이 아니라 "중심"

- **왜 중심:** "기존과 뭐가 다른지"(대조·유추)를 쓰려면 **'기존'을 기억하고 있어야** 한다. X를 Y와 비교하려면 Y를 예전에 배워 KB에 갖고 있어야 함. **대조 품질 = 기억의 함수.**
- **CoALA 3종 매핑:** 의미기억 = 개념 KB(대조 근거) · 에피소드 = `lessons`(Reflexion) · 절차 = 프롬프트·프로바이더.
- **단계적 구현:** 최소형(초기) = "본 것" 로그로 **신규성 판단** → 완전형(이후) = 개념 KB로 **대조·자기학습**. (Co-STORM의 "계속 갱신되는 마인드맵"과 같은 취지.)

---

## 8. 에이전트 경계 (논문 근거로 못 박기)

- **모델이 제어 = 에이전트:** Triage 판단 · Reader "더 찾자"(ReAct) · Author 집필 · Memory 쓰기(학습).
- **결정론 = 비에이전트:** Scout 발견·신규성 · 본문 fetch 실행 · Fact-Check(L1·번역대조) · 지표계산 · 렌더링.
- **근거:** Anthropic(제어 흐름을 모델이 쥐면 에이전트) · CoALA(의사결정은 모델, 실행은 코드 가능) · ReAct(관찰-추론-행동 루프) · Reflexion(실패 성찰→기억) · STORM/Co-STORM(조사→집필 2단계·마인드맵).
- **정직한 천장 ~80/100:** 검증 코어를 일부러 결정론으로 두므로 100은 목표가 아니다. "검증기를 누가 검증하나" — 앵커는 LLM 판단 밖에 있어야 닻이 된다.

---

## 9. 기존 파일 → 새 역할 (버리는 것 없음)

**고쳐서 재사용:**

- `schema.py` → 교과서 형식 그대로 (한국어·원문 텍스트 필드만 추가)
- `collector/` (trends·providers·engine·robots·rate_limit) → **Scout·Tracker의 토대**, 거의 그대로
- `shared/llm/` → 집필·번역에 그대로 사용
- `analyst/writer.py` → **Author** (한국어 번역·대조유추 강화)
- `verifier/anchoring.py` → **Fact-Check** (+번역 대조 추가)
- `dashboard/` → **한국어 대시보드** (신선도·원문 링크 추가)
- `metrics/` → 배경으로 유지
- `pipeline/run.py` → "한 번 도는 경로", 이 위에 **ReAct 루프**를 얹음

**새로 만드는 것(현재 없음):** Scout · Triage · **본문 수집**(그 "반쪽" 구멍) · **Memory/KB** · **Scheduler/watcher** · **에이전트 루프**.

## 10. 빌드 순서 (에이전트 작동 순서 그대로)

1. **Scout** (+최소 Memory: `seen` 로그로 신규성) — `trends.py` 위에
2. **Triage** (교과서 감 판단, 사이클당 상위 N)
3. **Tracker 본문 수집** — 공식 문서 본문 fetch (반쪽 구멍 메우기)
4. **Reader + ReAct "더 찾자"** — 되돌림 결정점
5. **Author** (한국어 번역·대조유추) — `writer.py` 확장
6. **Fact-Check** (+번역 대조) — `anchoring.py` 확장
7. **Memory 완전형**(개념 KB) + Reflexion `lessons`
8. **Dashboard** 한국어·신선도·원문 링크
9. **Scheduler/watcher** 로 전체를 실시간 루프로 감쌈

> 각 조각은 **독립 호출 · 구조화된 결과**(ReAct 호환)를 유지한다. 커밋·`WORKLOG.md`·`ERRORS.md` 기록은 계속(과제 핵심 증거물).

## 11. 정직한 경고 & 안전장치

- **완전 자율 루프는 오류가 누적**된다(루프마다 최약 고리 실패율이 곱해짐 — Anthropic).
- 안전장치 셋: **① 사이클당 주제 상한**(예: 상위 3) **② 결정론 검증 게이트**(지어낸 것 차단) **③ "미확인" 표기**.
- **비용캡**(토큰·호출 상한) · **무진전 가드**(2회 연속 개선 없으면 중단·정직 표기).

---

## 12. 성공 기준 (채용 과제 관점)

- **데모:** 방금(수 시간 내) 뜬 기술 1건을 에이전트가 **스스로 골라 → 공식 문서 읽고 → 한국어 교과서 생성 → 원문 대조 통과 → 대시보드에 "N시간 전"** 으로 표시.
- **증거:** `WORKLOG`(막힘→뚫음) · `ERRORS`(AI가 틀린 순간과 교정) · 커밋 이력. **"AI를 어떻게 부렸나"가 핵심 제출물.**
