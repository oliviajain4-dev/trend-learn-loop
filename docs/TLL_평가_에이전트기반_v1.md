# TLL 평가 — 에이전트 기준 채점 & 재설계 (에이전트성 v1)

> 작성: 2026-07-10 · 목적: TLL이 "얼마나 에이전트인가"를 **동료심사된 에이전트 문헌**을 외부 기준으로 삼아 채점하고, 논문 근거로 "정당하게 에이전트가 되는 지점"만 콕 집어 재설계한다.
> **짝 문서**: `TLL_평가_논문기반_v1.md` (품질·충실도 축). 이 문서는 **에이전트성(agenticness)** 축이며, 두 점수는 서로 다른 것을 재므로 **더하지 않는다.**
> **정직 고지 (핵심)**: 아래 채점 루브릭은 CoALA(서술적 개념틀)를 **점수화하도록 각색한 나의 구성물**이다. 가중치는 논문이 아니라 판단이며, "워크플로우 vs 에이전트"의 경계는 Anthropic에서, 루프·학습 기준은 ReAct·Reflexion에서 온 **합성**이다. 실측이 아니라 설계 성숙도의 상대 비교로 읽어야 한다.

---

## 0. 두 축을 혼동하지 말 것

| 축 | 재는 것 | 문서 | 현재 |
|---|---|---|:--:|
| 품질·충실도 | 산출된 이해가 얼마나 근거 있고 검증됐나 | `TLL_평가_논문기반_v1.md` | ≈ 83 |
| **에이전트성** | 시스템이 얼마나 에이전트 구조인가 | **이 문서** | **≈ 28** |

두 축은 독립이다. 훌륭한 워크플로우(품질↑)이면서 에이전트성이 낮을 수 있고, 그것은 결함이 아니라 설계 선택일 수 있다.

## 1. 문헌 근거 (실제 논문, 검증됨)

| # | 논문 | 출처 | TLL에 주는 것 |
|---|------|------|---------------|
| A1 | **CoALA** — Cognitive Architectures for Language Agents | Sumers, Yao, Narasimhan, Griffiths, TMLR 2024 (arXiv:2309.02427) | 에이전트를 3축으로 분해: 메모리 / 행동공간 / 의사결정 |
| A2 | **ReAct** — Synergizing Reasoning and Acting in Language Models | Yao et al., ICLR 2023 (arXiv:2210.03629) | 추론과 행동을 번갈아 생성하는 루프. 추론이 계획을 세우고 갱신, 행동이 외부 정보를 가져옴 |
| A3 | **Reflexion** — Language Agents with Verbal Reinforcement Learning | Shinn et al., 2023 (arXiv:2303.11366) | 실패를 언어로 성찰해 에피소드 메모리에 쓰고 다음 시도 개선 |
| A4 | **Building Effective Agents** | Anthropic, 2024 | 워크플로우(미리 정한 코드 경로) vs 에이전트(LLM이 흐름을 동적으로 지휘)의 경계. "가장 단순한 해법부터" |

### 1-1. CoALA 3축 요약 (정확판)

- **메모리**: 작업기억(단기) + 장기기억 3종 — 에피소드(경험), 의미(지식), 절차(코드·프롬프트·가중치).
- **행동공간**:
  - 내부 행동 — 검색(장기기억 읽기), 추론(LLM으로 작업기억 갱신), **학습(장기기억 쓰기)**.
  - 외부 행동 — grounding(도구·API·환경).
- **의사결정**: 계획(추론·검색으로 행동을 제안·평가·선택) → 실행(선택된 grounding/learning 수행). 이 사이클이 main 루프처럼 반복.

> 보정 노트: 이전 초안은 내부 행동을 "추론·검색"으로만 적었으나, CoALA에서 **학습(쓰기)도 내부 행동**이다. 아래 E항목(자기성찰)은 이 learning 행동과 memory 저장이 교차하는 지점이다.

핵심 교훈 한 줄: **에이전트냐를 가르는 건 "LLM을 쓰느냐"가 아니라 "제어 흐름(다음 행동 선택)을 모델이 쥐느냐"이며, 골라진 행동 자체는 결정론 코드여도 된다.**

|---|------|------|:---:|

## 3. 채점: 현재(Phase 1) vs 개선후

| 항목 | 현재 | 근거(현재) | 개선후 | 개정 내용 |
|------|:--:|-----------|:--:|-----------|
| A 의사결정 | 1.0 | 고정 파이프라인. 모델은 집필·검증만, 다음 단계를 못 고름 | 4.0 | 재수집/재집필을 **모델이 지표 보고 결정** (grounding 행동 선택) |
| B 행동공간 | 2.5 | 외부(수집 API)·내부(추론·검색) 행동이 **존재하나 코드가 순서대로 호출** | 4.0 | 모델이 "어느 소스를 다시 칠지"를 제안·평가·선택 |
| C 루프·피드백 | 1.5 | Phase 1은 선형. 지표를 재지만 행동으로 되먹이지 않음 | 4.0 | 지표를 관찰해 다음 행동을 바꾸는 ReAct 루프 |
| D 메모리 | 1.0 | 작업기억(컨텍스트)뿐, 장기기억 없음 | 3.5 | `lessons`(에피소드) + KB(의미) + 프롬프트·프로바이더(절차) |
| E 자기성찰 | 1.0 | Phase 1에 없음 (Reflexion은 Phase 3) | 4.0 | 실패 성찰을 메모리에 기록·재사용(Reflexion) |

### 가중 총점
```
현재  = 30·0.20 + 20·0.50 + 20·0.30 + 15·0.20 + 15·0.20
      = 6 + 10 + 6 + 3 + 3  = 28 / 100
개선후 = 30·0.80 + 20·0.80 + 20·0.80 + 15·0.70 + 15·0.80
      = 24 + 16 + 16 + 10.5 + 12  ≈ 78.5 / 100
```

**에이전트성: 약 28 → 79.** 현재 28점은 실패가 아니라 정확한 진단이다 — Phase 1은 의도적으로 워크플로우다.

## 4. "정당하게 에이전트가 되는 지점" — 콕콕 (억지 아님)

CoALA 의사결정 사이클(제안·평가·선택)에 실제로 부합하는 지점만 짚는다.

1. **재수집 결정** — 검증 결과 출처가 부족하면 모델이 "더 찾자"를 선택. grounding 행동을 모델이 고르는 것 = CoALA 의사결정 그 자체. ✅
2. **재집필 결정 (Reflexion)** — 충실도 미달 시 실패를 성찰해 메모리에 쓰고 다음 시도 개선. ✅
3. **행동공간이 실재함** — TLL은 이미 외부행동(HN·GeekNews·YouTube API)·내부행동(추론=집필, 검색=출처조회)을 보유. action space가 명목이 아니라 실재하며, "선택"만 모델에 주면 됨. ✅
4. **메모리 골격이 이미 설계에 있음** — `lessons`→에피소드, KB→의미, 프롬프트/프로바이더→절차로 CoALA 장기기억 3종에 자연 매핑. 억지가 아니라 씨앗이 존재. ✅

---

## 5. 에이전트로 만들면 안 되는 지점 (정직하게: 없음/해악)

- **검증(CoVe)·L1 문자열 앵커링·지표계산·HTML 렌더링** — 에이전트 케이스 **없음**. 결정론(코드)이 정답인 영역.
  - L1 앵커링을 비에이전트로 두는 이유: ① 검증기가 LLM 판단이면 잡으려는 환각을 검증기가 저지름("검증기를 누가 검증하나"), ② 문자열 대조는 재현성(같은 입력→같은 판정) 보장, LLM은 비결정론, ③ 더 싸고 빠르고 정확 = Anthropic "가장 단순한 해법", ④ 앵커는 LLM 판단 밖에 있어야 닻 역할을 함. 에이전트화하면 닻이 풀림.
  - CoALA 관점: 이는 grounding 행동을 결정론으로 **실행**하는 것이며, 의사결정만 모델이 하고 실행은 코드여도 논문상 모순 없음.
- **완전 자율 플래닝** (조사 전략 전체를 백지에서 모델이 수립) — 가능하지만 오류 누적(루프마다 최약 고리 실패율이 곱해짐) 위험. 반환각 목표와 상충. **하지 말 것 (점수용 억지).**

## 6. 개선 우선순위 (세 등급)

**① 품질↑ + 에이전트성↑ (강력 추천)**
- 재수집·재집필 루프(전환점 1·2). 출처 부족·충실도 미달 시 모델이 되돌림 → 반환각 미션에 직결, A·C 항목 상승. 최고 레버리지.
- Reflexion `lessons` 메모리 — 나쁜 출처·실패 패턴 회피. D·E 상승 + 품질 기여.

**② 에이전트성↑, 품질 기여 중간 (선택)**
- 다관점 확장을 모델이 동적 선택(전환점 3). STORM식 고정 다관점이 이미 커버하므로 한계효용 중간.

**③ 하지 말 것 (라벨용 억지, 해악)**
- 검증·지표·렌더링의 에이전트화. 완전 자율 플래닝.

## 7. 최종 비교 & 정직한 천장

| | 품질 점수 (기존 축) | 에이전트성 (이 문서) |
|---|:--:|:--:|
| 현재 (Phase 1) | ≈ 83 | ≈ 28 |
| 개선후 | ≈ 83 (거의 동일, 실측 시 오히려 상승 여지) | ≈ 79 |

**정직한 천장:** 에이전트성의 현실 상한은 **~80이지 100이 아니다.** TLL의 검증 코어(결정론 앵커링)는 의도적으로 비에이전트여야 하며, 이를 에이전트화해 90·100을 노리는 순간 프로젝트 정신(반환각·측정된 신뢰)을 배신한다. 따라서 **"~80 = 적정 에이전트성"이 진짜 목표**이고, 그 이상은 억지다. 이 절제 자체가 측정·근거 있는 판단의 예시다.

## 8. 한 줄 결론 & 다음 단계

**TLL = 결정론적 검증 코어를 감싼, 결정지점에만 얇은 에이전트 제어층을 얹은 하이브리드.** 이렇게 설계하면 "에이전트를 만들었다"를 근거를 갖고, 그것도 "여기는 워크플로우 / 여기부터 에이전트 / 여기는 일부러 비에이전트"까지 구분해 정직하게 말할 수 있다. 이 구분 능력이 채용 과제의 "검증과 판단"에 직결된다.
