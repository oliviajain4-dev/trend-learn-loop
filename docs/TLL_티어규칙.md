# TLL 티어 규칙 문서 — 동물 계급 = 주식처럼 수치화된 기준

> 목적: "호랑이·치타" 같은 직관적 딱지 뒤에, **정량적이고 재현 가능한 숫자 규칙**을 명시한다.
> 사람이 감으로 정하지 않는다 — 신호에서 계산된 값이 임계선을 넘으면 자동으로 계급이 정해진다.
> (이 문서 = 규칙의 단일 출처. 코드 `tll/rank/score.py`·`tll/rank/tier.py` 는 이 문서를 그대로 구현한다.)

---

## 0. 한눈에

- 기술을 **주식처럼** 본다. 단, **한 개의 종합점수로 합치지 않는다.** 두 개의 독립된 축으로 본다.
- **축① 채택(adoption)** = "얼마나 실제로 쓰이나(무겁게 쌓인 자산)". 별·포크·이슈·논문 수. 천천히 쌓이고 천천히 빠진다.
- **축② 주목·모멘텀(attention·momentum)** = "지금 얼마나 뜨나(가벼운 열기)". 커뮤니티 화제 + 최근 성장률. 빨리 오르고 빨리 식는다.
- 두 축의 **조합**이 동물을 정한다. 예) 채택 높고 + 지금 뜨는 중 = 🐯 호랑이. 채택 낮은데 + 확 뜸 = 🐆 치타.
- 여기에 **나이·재등장·가짜여부**를 더해 8계급으로 나눈다.

이 틀은 세 가지 표준 이론과 맞물린다:
- **로저스 혁신확산 S곡선** (혁신가 2.5% → 초기수용 13.5% → 초기다수 34% → 후기다수 34% → 지각수용 16%) — "채택 축"이 곧 이 곡선 위 위치다.
- **가트너 하이프사이클** (발단 → 부풀린 기대의 정점 → 환멸의 골 → 계몽의 경사 → 생산성 고원) — "주목 축"이 곧 이 사이클 위 위치다.
- **기술수명주기** (태동 → 성장 → 성숙/포화 → 쇠퇴) — 두 축 + 나이가 이 단계를 가른다.

## 1. 측정하는 숫자 (정의·계산·임계값)

모든 값은 신호 로그(`tll/signals`)에서 **결정론적으로** 계산된다. LLM 판단 아님.

### 1-1. 채택 A (adoption) — "얼마나 쓰이나" (참여 중심 · 포화 정규화 0-100)
- **별(★)은 약한 지표다** — 북마크·인기 신호일 뿐이고 조작 가능(가짜별 수백만 논문). 그래서 **채택 '크기'는 참여 중심**으로 잰다:
  `크기 = 포크×1 + PR×1 + 이슈×0.5 + 별×0.1` (별은 10%로 **강등**). arXiv 기법은 `크기 = 총 논문수`(최근수는 크기에 안 씀).
- **정규화(스케일링):** 손앵커 대신 **포화함수 `A = 100·크기/(크기+K)`** 로 0-100. 채널별 K(github 8,000 / arxiv 1,500), 여러 채널이면 채널 간 max.
  - 예) transformers(포크2.8만)→84 / langchain(포크1.4만)→74 / RAG(논문4,200)→74 / **별만 9만·참여없음→53**(별 강등 효과).
- **채택 밴드(0-100, 튜닝 가능):** 낮음 `<38` · 중간 `38–60` · 높음 `60–78` · 거대 `≥78`.
- 신뢰(합의): 독립 지표 ≥2(`corrob_kinds`). **arxiv_recent 는 arxiv_total 과 같은 소스라 안 센다**(동일소스 중복 방지). **단일소스는 확정 상위 티어 금지** → 크면 거북이 '잠정'.

### 1-2. 주목 Att (attention) — "지금 화제인가"
- 계산: 커뮤니티 점수(HN/해커스뉴스 등 버즈)를 **반감기 지수감쇠**로 합산. 오래된 화제는 반감기(기본 3일)마다 절반으로 죽는다.
  - `Att = Σ points · 0.5^(경과일 / 반감기)`.
- **주목 임계:** 화제 `Att ≥ 50`, 폭발 `Att ≥ 300`.
- 버즈는 빨리 죽는 게 핵심 — 3일 전 700점짜리 화제는 오늘 이미 크게 깎인다(하이프사이클 "정점"의 덧없음).
- **소스 다양화(HN 편중 방지):** 지금 소스 = HN·긱뉴스(한국)·Reddit. 버즈를 낸 **서로 다른 소스 수(`buzz_sources`)**를 센다.
  · **단일소스 화제는 빨리 🦟하루살이로 강등**(노이즈 가능성↑), **여러 소스서 뜨면 오래 🐆치타로 유지**(진짜 화제).
  · **공식/벤더 발표 = 자랑·허세(자기홍보) → 버즈 0.3 할인**. 커뮤니티(유기적 관심)는 온전히 1.0. (300점 공식발표 → 90)

### 1-3. 모멘텀 G (adoption growth) — "채택이 크는 중인가"
- 계산: 최근 창(기본 14일) 동안 채택 지표의 **증가분 합**. `G = Σ_kind (latest − 창_시작값)`.
- **베이스라인 규칙(중요):** 창 시작 시점 이전의 값이 **없으면 성장은 0으로 둔다**(못 잰다).
  - 이유: 첫 관측을 "0 → 폭증"으로 오인하지 않기 위해. 성장은 **최소 2회 관측**이 있어야 진짜다.
- **상승 판정:** `G > 0` **이면서** 상승한 지표가 ≥2종(`rising_kinds ≥ 2`). 한 지표만 오른 건 노이즈로 본다.
- 밴드: 하락 `G < 0`, 평탄 `G ≈ 0`, 상승 `G > 0 & rising_kinds≥2`, 급상승 `상승 & 최근>직전(가속)`.

### 1-4. 나이 age — "생애 어디쯤"
- 계산: **진짜 생성일만** 사용 — GitHub `created_at` 또는 최초 논문일. (우리가 '처음 본 날 `first_seen`'은 나이가 **아니다**. 그래서 트렌드로 방금 처음 본 것을 "만든 지 0일"로 표시하지 않는다.)
- 밴드: 신생 `<0.5년`, 젊음 `0.5–2년`, 성숙 `2–5년`, 노장 `≥5년`.

### 1-5. 재등장 R (recurrence) — "반짝인가 지속인가"
- 계산: 서로 다른 날짜에 관측된 횟수. `R = distinct 관측일 수`.
- `R = 1`: 첫 관측 → **모든 계급에 '잠정' 딱지**. `R ≥ 2`: 지속 확인. `R ≥ 4`인데 채택 전환 없으면 강등(하루살이).
- 이론 근거: 유행(fad)은 한 번 튀고 사라지고, 추세(trend)는 여러 번 꾸준히 돌아온다.

### 1-6. 합의·가짜 (corroboration / fake)
- 합의: 위 모든 승격은 **독립 신호 ≥2종**이 뒷받침해야 함(단일 지표 불신).
- 가짜 판정: **별은 (측정된) 성장으로 오르는데, (측정된) 실제 참여(이슈·PR·포크)는 정체**면 `fake=True`.
  - 근거: GitHub 별의 상당수가 조작(2024.7 기준 별 50개+ 저장소의 약 16%가 가짜별 캠페인 연루). 별 = 인기 신호일 뿐 채택이 아님.

### 1-7. 소스 역할·융합 — "어디서 뜨느냐"를 제대로 반영

소스마다 **역할**이 다르다. 하나의 min-max 점수로 뭉개지 않고 역할별로 반영한다.

| 소스 | 재는 것(축) | 생애 위치 | 독립성 | 가중 |
|---|---|---|---|---|
| 공식/벤더(RSS) | 존재·최신 **발표(발견)** | 선행(최초) | ✗ 자기홍보 | 주목 0.5 · 중요도 투표 **제외** |
| HN·Reddit·긱뉴스 | 유기적 관심 | 초·중 | ✓ | 1.0 |
| YouTube | 실무·교육 관심(대두) | 중 | ✓ | 0.8 |
| arXiv 논문 | 연구 기반·엄밀성 | **후행**(늦음) | ✓ | 채택축·고품질 |
| GitHub | 실사용 | 중·후 | ✓ | 채택축(별은 강등) |

- **자랑 vs 허세 = 텍스트가 아니라 "남이 독립적으로 받아주냐".** 공식 발표 + 커뮤니티·유튜브·논문·GitHub 독립 반응 → **자랑(진짜)**. 공식만 → **허세** → 🌱새싹에 머물다 🦟하루살이. (그래서 공식은 **발견 신호로만**, 독립 투표엔 제외.)
- **논문은 대체 불가(최고 품질)지만 후행** — 어제 나온 기술은 아직 논문 없음 → **없다고 벌주지 않음**(공식·커뮤니티로 잡음). **논문 수 = 연구량이지 정착 아님**(단일소스면 거북이 잠정).
- **생애 흐름을 소스로 읽는다:** 공식만→🌱새싹 · +커뮤니티→🐆치타 · +유튜브+채택↑→🐯호랑이 · +논문 쌓임+평탄→🐘코끼리 · 한 번 튀고 침묵→🦟하루살이.
- **정규화는 min-max 아님** — 코호트 바뀌면 불안정 → 소스별 **포화함수**(§1-1).


## 2. 동물 계급표 (정량 기준 → 동물)

**판정은 위에서 아래로 먼저 걸리는 것 채택(우선순위 순).** 모든 숫자는 §1의 밴드.

| 순위 | 동물 | 정확한 수치 조건 | 생애단계(이론) | 행동 |
|---|---|---|---|---|
| 1 | 🐺 하이에나 | `fake=True` (별↑ & 실제참여 정체) | 조작·파생 | 걸러 |
| 2 | 🐘 코끼리 | 합의 & `A ≥ 78`(거대) & **내구성** & 안 뜸 & 안 하락 | 정착·기반 | 필수·기반 |

> **내구성 = (신뢰 나이 ≥4년) 또는 (측정된 평탄 + 재등장 ≥3).** 신뢰 나이는 **GitHub 저장소 생일만** — arXiv 최초논문일은 불량 대리라 안 씀. 그래서 RAG(arxiv 단일소스)·젊은 저장소(랭그래프)는 코끼리 불가.
| 3 | 🦕 공룡 | 합의 & 과거 높음(`A ≥ 58`) & `G < 0`(하락) | 쇠퇴 (대체되는 중) | 참고만·이관 검토 |
| 4 | 🐯 호랑이 | 합의 & `A ≥ 58`(높음) & **뜨는 중**(상승 `rising_kinds≥2` **또는** 화제 `Att≥50`) | 성장기 핵심 (S곡선 급상승, '계몽의 경사') | **지금 배워라** |
| 5 | 🐢 거북이 | 합의 & `A ≥ 40`(중간~높음) & `G ≈ 0`(평탄) & 화제 아님 | 안정적 니치 (꾸준하나 기반급은 아님) | 참고·필요할 때 |
| 6 | 🐆 치타 | `Att ≥ 50`(화제) **또는** 급상승, 그런데 채택 미검증(`A < 58`) & 나이 신생~젊음 | 초기수용·정점 향함 (미검증) | 지켜봐(오를수도/식을수도) |
| 7 | 🌱 새싹 | 신생(`<0.5년` 또는 `R=1`) & 신호 부족(`A < 40`) & 약한 상승/주목 | 태동·발단 (신호 모으는 중) | 관측 시작 |
| 8 | 🦟 하루살이 | 주목 반짝했다 식음 & 채택 `A0`(≈0) — 또는 `R≥4`인데 미전환 | 유행 실패 (정점→골 추락) | 무시 |

- **잠정 딱지:** `R = 1`(첫 관측)이면 호랑이·치타·코끼리라도 "· 잠정". 두 번째 관측부터 확정.
- **핵심 설계 원칙:** 호랑이(지금 배워라)는 **드물어야** 한다. "채택 높다"만으로 호랑이를 주지 않는다 — 반드시 **뜨는 중(모멘텀 or 화제)**이어야 한다. 안 그러면 §4의 "호랑이 24마리" 사태가 난다.

## 3. 코끼리 재설계 — 왜 30마리가 틀렸나

**증상:** GitHub 자동 발견이 별 많은 저장소 수십 개를 한꺼번에 등록 → 전부 "채택 높음" → 죄다 한 계급으로 쏠림.
초판에선 이게 다 호랑이였고(잘못), 1차 수정 뒤엔 다 코끼리가 될 판이었다(역시 잘못).

**당신 지적이 정확하다:** 코끼리는 "매우 안정적이고 기업이 당연히 쓰는, 사실상 정해진 소수"다(리눅스·포스트그레스·쿠버네티스급). **많을 수가 없다.**

**해결 = 코끼리를 "억지로 줄이는" 게 아니라 정의를 정확히 한다. 진짜 코끼리면 코끼리로 제대로 대우(설명서까지).**
개수를 목표로 깎지 않는다 — 조건을 통과하면 몇이든 코끼리다. 개수는 결과일 뿐.

- 🐘 코끼리 = `A ≥ 78`(거대·참여중심) **AND 내구성** **AND** 안 뜸. **내구성 = 신뢰나이(GitHub 생일 ≥4년) 또는 (측정된 평탄 + 재등장≥3).** arXiv 최초논문일은 나이로 **안 씀**(불량 대리).
- 🐢 거북이 = 채택은 탄탄한데(중간~높음) 아직 나이가 안 됐거나 지금 특별히 뜨지 않는 **꾸준한 도구**.

**중요: 나이만으로는 절대 코끼리가 못 된다.** "오래됐다"만으론 부족하고 "중요(거대 채택)"가 반드시 함께여야 한다.
- 첫 관측이면 아무리 커도 코끼리 **아님** → 🐢거북이 잠정(정착 미검증). 며칠 걸쳐 **평탄**이 확인돼야 코끼리.
- 크는 중이면 → 🐯호랑이. 낮은 채택이면 → 🦟하루살이/🌱새싹. **오래됨만으론 절대 코끼리 안 됨.**

이렇게 하면 코끼리는 "정말 그런 것"만 남고, 나머지 안정 도구는 거북이가 흡수한다.

## 4. 새 동물 두 마리 (직관 보강)

기존 6마리(호랑이·코끼리·치타·공룡·하루살이·하이에나)로는 두 빈칸이 생겨서 추가한다.

- 🐢 **거북이 — 꾸준·안정하나 기반급은 아님.** 느리지만 오래 간다. 채택 중간~높음 + 평탄. "지금 급히 배울 건 아니지만, 필요하면 믿고 쓰는" 도구. (코끼리 쏠림을 흡수하는 핵심 완충 계급.)
- 🌱 **새싹 — 갓 등장, 판단 보류.** 신생 + 신호 부족 + 약한 꿈틀거림. 치타(이미 확 뜬 것)보다 이르다. "떡잎"만 본 상태. 물 주며 지켜본다. 며칠 뒤 치타/호랑이로 크거나, 하루살이로 사라진다.

> 더 세분화 여지: 원하면 '🐜 개미(작지만 협업·생태계 형성)', '🦂 전갈(작지만 보안·리스크 신호)' 등도 규칙만 정하면 추가 가능. 다만 계급이 너무 많으면 직관을 잃으니 8개를 기본으로 제안한다.

## 5. 개념의 종류 — 도구 / 기법 / 자료 (메타-repo 문제)

지금 티어에 **자료 모음**이 기술인 척 껴 있다(awesome-llm-apps·RAG_Techniques·prompts.chat 등). 이걸 정리하려면 먼저 "이게 뭔 종류냐"를 판별해야 한다.

**개념을 3종으로 분류한다:**

1. 🔧 **도구/프레임워크** (langchain, ollama, milvus…): 실제로 설치·실행하는 소프트웨어. → **저장소 신호(별·포크·이슈)로 채택 측정.** 동물 계급 부여.
2. 🧠 **기법/개념** (하네스 엔지니어링, RAG, 프롬프트 엔지니어링, 에이전트 워크플로…): 특정 제품이 아니라 **하는 방식**. 저장소가 없다. → **용어 빈도로 측정**(§6).
3. 📚 **자료/모음** (awesome-*, -tutorials, roadmap, papers-list…): 링크·강좌 묶음. 배우는 "기술"이 아님. → **티어에서 제외**, 별도 '학습자료' 서랍으로.

**분류 판정 기준(값싼 우선, 애매하면 LLM 1콜):**
- 이름 패턴: `awesome-`, `-tutorial(s)`, `-examples`, `-cookbook`, `roadmap`, `-list`, `papers`, `resources`, `guide` → 자료일 확률 높음.
- 저장소 구성: 코드 거의 없고 대부분 Markdown/링크 → 자료.
- 토픽 태그: `awesome-list`, `learning-resources`, `tutorial` → 자료.
- 최종 애매하면 LLM 한 줄 분류: *"이 저장소는 (1) 실행 도구 (2) 기법·개념 (3) 링크·자료 모음 중 무엇?"* → 라우팅.

이건 "필터로 버리기"가 아니라 **분류해서 알맞은 자로 재는 것**이다. 자료는 버리지 않고 '학습자료'로 따로 보관(원하면 대시보드 하단 서랍).

## 6. 소프트웨어가 아닌 개념 잡기 — "하네스 엔지니어링" 같은 것

**문제:** '하네스 엔지니어링', 'RAG', '컨텍스트 엔지니어링'은 **하나의 저장소가 아니다.** 그래서 GitHub 저장소 검색으로는 절대 안 잡힌다. 그런데 IT 현장에서 실제로 중요하게 쓰인다.

**해결(구현됨) = "용어 빈도 신호"를 깊게 판다.** 저장소 대신 **말의 확산**을 센다.
> 코드: `signals/terms.py` — HN·arXiv 제목에서 **약어(RAG·MCP) + 헤드명사 구("X engineering"→하네스 엔지니어링)**를 뽑아 빈도 임계 넘으면 🧠기법 자동 등록. 내가 언급 안 해도 잡힘. community(용어빈도)+arxiv(논문) = **2소스 합의** → 상승 관측되면 거북이→호랑이 승격.
- **논문(arXiv):** 그 용어가 제목·초록에 등장한 논문 수 + 최근 6개월 수 + 최초 등장일. (이미 부분 구현 — `tll/signals/arxiv.py`.)
- **커뮤니티 제목:** 해커뉴스/커뮤니티 글 제목에 그 용어가 나온 빈도의 **추세**(이번 달 vs 지난 달).
- 이 둘을 합쳐 "기법 개념"의 채택(누적 언급)·모멘텀(언급 증가율)을 만든다 → 도구와 똑같이 동물 계급에 태운다.

즉 **도구는 저장소로, 기법은 용어 빈도로** 잰다. 축(채택/주목)과 동물표는 그대로 쓰고, "무엇을 세느냐"만 개념 종류에 맞춘다. 이게 "범위를 넓히지 않고 한 신호(용어 빈도)를 깊게" 파는 방향이다.

## 7. 콘텐츠 — 교과서 vs 설명서 (왜 코끼리에 설명이 없었나)

**증상:** 수십 개 기술 중 교과서가 몇 개뿐. 코끼리인데 설명이 없다 → 말이 안 됨.

**원인(정직):** 지금 '교과서'는 **딱 한 경로**에서만 나온다 — 트렌드 정찰(커뮤니티/HN 글) → 읽기(Reader) → 집필(Author). 즉 **읽을 본문(기사)이 있었던 것만** 교과서가 생긴다.
GitHub 자동 발견으로 들어온 개념(langchain·mlflow…)은 **별·포크 신호만** 받고 Reader/Author를 **안 거친다.** 그래서 설명이 비어 "아직 안 배움"으로 뜬다. 코끼리(발견된 거인)가 설명이 없는 이유가 이것.

**해결(구현됨) = 모든 개념에 최소 '설명서'를 만든다. 2단계 콘텐츠로 분리:**
> 코드: `author.write_manual`(짧은 집필) + `author.manuals.backfill_manuals`(설명 없는 개념에 README 근거 설명서) + 루프 배선. 새 개념만·사이클당 6개까지(비용).
- 📖 **교과서(깊음):** 읽을 본문 기사가 있을 때. 지금처럼 유사·대조 중심의 긴 글 + 충실도 검증.
- 📝 **설명서(가벼움):** 본문 기사가 없는 발견형 개념용. **저장소 README/설명** 또는 **대표 논문 초록**을 근거로 짧게(3~5문장) 집필. "이게 뭐고, 뭐랑 비슷하고, 언제 쓰나".
- 규칙: **모든 개념은 최소 설명서를 가진다.** 본문 기사가 확보되면 교과서로 승격.
- 화면 표기도 정직하게: 깊은 건 "교과서", 가벼운 건 "설명서"로 라벨.

**비용 주의:** 발견 개념마다 설명서 1콜 → 개념이 많으면 LLM 호출↑. 그래서 **새 개념일 때 1회만** 생성(캐시), 이미 있으면 재사용. 비용은 관리>비용 콘솔에 그대로 집계.

## 8. 대시보드 — 계급 개수 + 신규(오늘/주/월)

상단에 **요약 바**를 둔다. (구현됨 — 대시보드 상단)
- **계급별 개수:** 🐯 N · 🐘 N · 🐢 N · 🐆 N · 🌱 N · 🦕 N · 🦟 N · 🐺 N (합계 M).
- **신규 유입:** 오늘 +N · 이번 주 +N · 이번 달 +N. (기준 = 개념의 `first_seen`이 그 기간 안.)
- 이러면 "무엇이 얼마나 쌓였고, 요즘 새로 뭐가 들어오나"가 한눈에 보인다(주식 시황판처럼).

## 10. 미해결·튜닝 포인트 (정직)

- **첫 관측 한 장으론 모멘텀을 못 잰다.** 그래서 처음엔 대부분 거북이/새싹으로 보이고, **며칠 돌려야** 성장률이 쌓여 호랑이가 갈린다. 이건 원리상 한계(시간이 필요). "잠정" 딱지가 그 표시.
- **임계값은 잠정 기본값.** A밴드·나이·주목 문턱은 실데이터로 몇 주 관찰 후 보정 대상.
- **폐쇄형·비공개 기술**(사내 도구, 비공개 API)은 저장소도 논문도 없어 여전히 사각지대.
- **기법 신호(용어 빈도)**는 동의어·약어(RAG=검색증강생성) 병합이 필요 — 개념 레지스트리의 별칭 기능으로 흡수 예정.
- **채널별 채택 스케일 차이(해결됨):** GitHub·arXiv 를 앵커 기반 0-100 채택지수로 정규화(§1-1). 이제 RAG(논문 4,200편→77.6)가 langchain(별 9만→82.5)과 나란히 '거대'로 잡힌다. 앵커 수치 자체는 실데이터로 미세보정 여지.
